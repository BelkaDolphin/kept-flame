# ゲーム企画書: 詰めタクティクス ―― 日替わり完全情報盤

作成日: 2026-07-24(第3回検討)
前提: `検討結果レポート_運営LLM版.md` で確定した「Seedspire v2」型構成(完全決定論・Cloudflare Pages・content/*.jsonのみで週次拡張・多方策simゲート・LLMは運営のみ)の上に載せるゲーム企画。
検討方式: 立案・改訂=Opus、敵対攻撃・再検証=Sonnet(計18エージェント・約67万トークン)。最終ジャッジのみFable 5がインラインで実施。

## 1. 結論

**推奨: 「詰めタクティクス」(戦略性・深さ重視案の改訂版)** — 3案中唯一、敵対検証R2で fatal 0 / major 0 に収束した。

一言でいうと: **「運も隠し情報もゼロ。全員が今日の同一盤面(固定デッキ・固定引き順・敵の全未来行動公開)を渡され、より少ないターンで解く詰将棋型カードパズル」**

| 要素 | 内容 |
|---|---|
| ジャンル | 完全情報・完全決定論の戦術最適化パズル(カード駆動、シングルプレイ) |
| 1日の遊び | 今日の盤面(2〜3戦連戦)を解く→基準スコア(Par)超えを詰める→凡例付き絵文字グリッドで共有 |
| プレイ時間 | 初回クリア3〜8分、最適化リトライ込みで10〜20分 |
| seed | `seed = hash(UTC日付)` のみ。コンテンツ版はseedに混ぜず manifest(日付→snapshot_id)で管理 |
| 週次運営 | カード/敵のJSON追加3件→決定論ゲート→snapshot確定→翌UTC日以降にのみ反映 |
| 実装 | 6週(上限。超過時のtrim順を明記済み) |

### 3案の顛末

| | 戦略性・深さ重視 | 習慣化・シェア重視 | 運営拡張性・実装最小重視 |
|---|---|---|---|
| 案 | 詰めタクティクス | Deck Daily(今日の3連戦) | 日替わり錬成(Daily Transmute) |
| R1 | fatal 2 / major 19 | fatal 2 / major 14 | fatal 2 / major 13 |
| R2 | **fatal 0 / major 0(収束)** | fatal 1 残存(工数7.6週で制約超過、圧縮後の定量再見積なし) | 改訂エージェントが出力失敗し未改訂(ドラフト+指摘のみで判定) |

3案とも共通して食らった致命傷は「**seedやカード抽選プールが最新のcontent/*.jsonに依存し、週次デプロイが当日・過去日の盤面を静かに書き換える**」問題。勝者はこれを「seed=日付のみ+日付→snapshot_idマニフェスト+不変スナップショット」で構造的に閉じた。もう1つの共通致命傷「ビームサーチ近似を『理論最良』と過大主張し、その上のバランス検証が全部崩れる」も、Parの再定義(時間制限探索の到達基準値)+詰み検出の二段構えで解消した。

## 2. ゲーム内容

### コアループ
1. 起動→UTC日付からseed導出、manifestでその日のコンテンツsnapshotを確定。本日の「固定デッキ(全カード公開)・固定引き順(完全公開)・2〜3戦の敵と全行動スクリプト」を決定論生成(全端末で完全同一)。**戦間ドラフトは無し**——ラン開始時点で最終戦までの全情報が一意に確定している。
2. 敵の全未来行動と自分の引き順を全て見た状態で、毎ターン「エネルギー内でどのカードをどの順・どの標的に切るか」を選ぶ。カード選択→対象選択→確定の2段階入力+ターン内アンドゥ(誤タップ事故対策)。
3. 全敵撃破でスコア確定(クリア+残HP+ターン効率+コンボ)。初回クリア直後に「あと何ターン短縮できるか」の伸びしろ差分を即時提示。
4. 同じ日を無制限リトライして手順を詰め、ベストをlocalStorage保存。ネタバレなしの結果グリッド(凡例付き: 🟩=効率ターン 💠=無傷 👑=Par超え)を共有。
5. 過去日はその日のsnapshotで再挑戦可能(いつ遡っても当日配信と完全一致)。

### ルール要点(ボット自動プレイ可能)
- 完全決定論・固定デッキ・ラン中のランダム要素ゼロ。エネルギー3/ターン、blockはダメージを先に相殺、敵は `intent_script` 通りの固定行動(プレイヤーに反応しない=単一エージェント最適化問題)。
- カード効果は固定op語彙(damage/block/draw/gain_energy/apply_status/条件分岐…)の組合せ。**条件フィールド(対象が特定status保持時のみ発動等)をローンチ時にengineへ実装し尽くし**、以降の新シナジーはJSON追加のみで成立させる(Deck Daily案のfatal対策をグラフト)。
- スコアはターン効率が主係数。コンボは1ターン最大1カウントとし「ターンを延ばして稼ぐ」歪みを排除(sim指標Fで回帰検出)。
- **数値演算は整数のみ(浮動小数排除)、丸め・適用順序をengineで厳密定義**——クロスプラットフォーム決定論の保証(Daily Transmute案からグラフト)。

### コンテンツJSONと週次運営
- 運営が触るのは `content/cards/*.json` と `content/enemies/*.json` のみ。`icon` はUnicode絵文字1文字を必須フィールドとし、バイナリ素材作業を発生させない(グラフト)。
- gate通過後に `content/versions/{snapshot_id}/` へ不変コピーを永続化し、`manifest.json` に「日付→snapshot_id」を追記。**デプロイは常に翌UTC日以降にのみ反映**、当日盤面は絶対に変わらない。
- バランス崩壊カードの退役は削除ではなく `disabledFrom` 指定(過去日の再現性を壊さない。グラフト)。
- 週3件の追加はプール構成比を動かし、以降生成される全デイリーの分布とメタを緩やかに変える(例: frozenシナジー3点セットで「凍結を撒いて追撃」の新最適ラインが誕生)。

### 決定論ゲート(gate.mjs、Node専用・クライアント非同梱)
- 直近120日ぶんのseedに対し、ランダム/貪欲/n手読み/時間制限つき探索ソルバーの4ボットを実行。**Parは「真の最適値」ではなく「時間制限探索の到達基準値」と定義**(UI表記も「基準スコア」)。
- 検出指標: (A)詰み=保守的下界チェック+構成的証明の二段構え(探索失敗を詰みと誤認しない) (B)自明解=ランダム上位5%点がPar90%超でreject (C)健全帯=n手読み勝率85〜98%+Par近傍に別解2本以上(スポイラー耐性) (D)支配カード=forced-appearance+ablation対照実験 (E)Par妥当性 (F)スコア単調性。
- 追加でグラフト: **ボットの乱数シードも盤面seedから派生固定**(CIのflaky化防止)、**ローンチ時ベースラインとの累積ドリフト監視**(週次±40%チェックだけでは緩やかなインフレを見逃す)、**push前にローカルで数十秒で回る軽量sim(dry-run)** を運営ツールとして用意(週1セッション30〜60分に収めるため。収まらなければ非同期gate運用に切替)。
- reject時は定型対処表(勝率上振れ→cost+1/value-1等)を参照、同一セッションで直せなければ翌週持ち越しが正式ルール(グラフト)。

### リテンション(サーバーなしで成立するもののみ)
自己ベスト更新とストリーク、発見した別解のコレクション、Par超えバッジ(運営継続前提の付加価値と位置づけ)、gate算出の想定達成率のローカル表示(「このParは想定上位X%の効率」)、凡例付きネタバレなし共有グリッド。完全情報ゆえ外部ソルバーで達成が無償化されうる構造的弱点は受容し、リテンション主軸をPar一点張りではなくプロセス指標に分散させる。

### 差別化
最も近い既存作『Fights in Tight Spaces』(敵の未来意図全表示のタクティクス)に対し、引き順まで固定公開して運要素を完全ゼロ化+全員同一seedの非同期比較+ブラウザ即プレイ・無料・アカウント不要。Slay the Spire公式Daily Climb等「同シード比較」自体は先行例があるため(習慣化案の検証で判明)、訴求は「同シードの初出」ではなく「Wordle的な即時性・共有性×詰将棋的最適化」に置く。

## 3. 実装スコープ(6週上限)

1. 共有 `/engine`(seed導出・manifest/snapshot読込・op解釈器・intent実行・スコア) — 1.5週
2. クライアントUI(完全情報表示・2段階入力+アンドゥ・伸びしろ差分・共有グリッド・報告ボタン=seed+snapshot_id+engine_version+操作列ハッシュ) — 1.5週
3. オンボーディング(gate対象外の固定「練習seed」を初回強制通過) — 0.5週
4. simulator+gate.mjs(4ボット・下界チェック・ablation・par.json生成・ローカルdry-run) — 1週
5. 初期コンテンツ(カード45〜60種・敵15〜20種)+初回バランス調整 — 1週
6. snapshotアーカイブ構造+週次運営フロー確立 — 0.5週

超過時のtrim順: ゴーストリプレイ削除→アニメ最小化→戦闘数2固定→別解オーバーレイ後回し。

## 4. 残存リスク(受容済み)

1. 完全情報ゆえ外部計算で最適手順を割り出せる(探索エンジンはクライアント非同梱にするが原理的に防げない)→プロセス指標への分散で受容。
2. 最短手順のテキスト拡散は防げない→Par近傍に複数別解を維持(gate指標C)して被害を薄める。
3. 運営が完全停止すると120日超の未来はPar未生成→クライアントの軽量フォールバック近似で表示(ゲーム本体と自己ベストは永続動作)。
4. ドラフト廃止によりビルド構築の快感は薄い→「最適化と別解発見の満足感」を訴求軸にする(意図したトレードオフ)。

## 5. 検討プロセスの注記

- 運営重視案「日替わり錬成」は改訂エージェントが構造化出力の再試行上限で失敗し、R2未完のままドラフト+R1指摘で判定した(fatal 2が未解消のため、いずれにせよ勝者にはならない)。ただし同案の攻撃で出た汎用的な対策(整数演算固定・simシード固定・累積ドリフト監視・ローカルdry-run・sim閾値の実測キャリブレーション)は推奨案にグラフト済み。
- 習慣化案「Deck Daily」は工数超過fatalが残ったが、condition語彙の先行実装・icon必須・disabledFrom・2段階入力・reject定型対処表・既存競合(StS Daily Climb / Rogue Roll)の事実確認は推奨案に取り込んだ。
