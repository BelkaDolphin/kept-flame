# 検討結果レポート: 8GB Surface Pro / 無料枠クラウドで Claude + ローカルLLM ゲームを企画〜運営する方法

作成日: 2026-07-24
検討方式: 多観点サブエージェント（ローカル完結派 / クラウド無料枠派 / ハイブリッド派）による立案 → 敵対的サブエージェント3体（コスト現実主義 / 技術実現性懐疑 / 運営持続性懐疑）による攻撃 → 改訂、を各案最大3ラウンド反復。事前にWeb調査（2026年時点のローカルLLM / AWS無料枠 / Claude料金 / 無料ホスティング）を実施。

> **プロセス注記（正直な開示）**: 最終ラウンドで審査員パネル3体とクラウド案への第3回攻撃がセッション使用量制限により実行できなかった。本レポートの統合判断はオーケストレーター（Claude本体）が3案の全文と全ラウンドの攻撃記録から直接行ったものである。クラウド案の「第3版」は第3ラウンドの敵対検証を受けていない点を割り引いて読むこと。

## 1. 結論

**最推奨: 案B「日替わりAIミステリー」（Cloudflare完結型・クラウド無料枠派の第3版）**

3案のうち、敵対検証で致命的欠陥（fatal）を全て潰しきったのはこの案だけである（R1: fatal2 → R2: fatal0）。他の2案は3ラウンド目でも fatal が残った。

- **どんなゲーム**: 「Daily Deduction」— 毎日0時(JST)に新しい推理問題を1問公開するWordle型ブラウザゲーム。容疑者3〜5人の証言から矛盾を見つけて犯人を当て、結果を絵文字でシェアする。
- **企画立案**: Claude Code（Pro $20/月）で設計。問題の「論理骨格」はTypeScriptの決定論ソルバが生成・一意解を機械検証し、文章化だけをLLM（Claude Haiku 4.5、月$2〜4）が行う。
- **実装**: Surface Pro上のClaude Codeで開発（repoはWSL2のext4側に置く、.wslconfigでメモリ6GB制限）。重い場合はGitHub Codespaces無料枠（月120コア時間）に逃がす。
- **管理運営**: Cloudflare Workers cron が週次で問題を自動生成、date駆動で毎日自動配信（0時に「実行される何か」が無いので配信は落ちない）。通報はHaikuが一次トリアージし高確度NGは自動差替まで完結。監視はBetter Stack + Healthchecks.io の無料2系統。人間の必須作業は**1日5分の通知確認＋月2〜3時間**まで圧縮。
- **コスト**: 定常 **月約4,700〜5,400円**（Claude Pro $20 + Workers Paid $5 + Haiku API $2〜4 + ドメイン、税・為替込み）。初年度総額の基準ケース約8.5〜9.5万円（開発期のMax昇格 最大$400のハードキャップ込み）。

### なぜこの案か（審査観点）

| 観点 | 評価 |
|---|---|
| 実現性 | 唯一 fatal 0 に到達。Phase 0（3週間・Pro $20のみ）に go/no-go の数値基準があり、ダメなら$25で撤退できる |
| 「運営まで全てLLM」への適合 | 3案中最も近い。配信・生成・通報対応・週次レポートが自動/LLM化され、人間は例外処理のみ |
| コスト予測可能性 | Anthropic spend limit + Cloudflare Budget alerts の二重ハードキャップで青天井を遮断 |
| 8GB Surface Proとの相性 | 実行系をクラウドに置くため、Surfaceは開発端末で足りる（最重要制約に抵触しない） |

**注意**: 「メモリ8GBでローカルLLMをゲームのリアルタイム応答に使う」構想自体は、敵対検証の結果 **3案すべてで棄却された**（旧世代CPUで1〜4 tok/s程度と推定され実用に耐えない）。ローカルLLM（Ollama + Qwen3 4B等）の現実的な使い所は「オフラインでのアイデア出し・テキストの事前バッチ生成」に限られる。この点をどうしても外せないなら案A（オフライン配布型）になるが、その場合「管理運営の完全自動化」は原理的に不可能というトレードオフを受け入れる必要がある。

|---|---|---|---|

| 定常コスト | 月2,300〜4,600円相当（間欠Claude+機材積立） | 月4,700〜5,400円 | 月$28〜34（約4,400〜5,300円） |

興味深い点として、独立に立案された案Bと案Cは敵対検証を経て**ほぼ同じ形（Cloudflare上の日替わり推理ゲーム＋週次バッチ生成＋静的配信）に収束した**。これはこの構成が制約に対する自然な最適解であることの傍証になっている。

## 3. 推奨案（案B）の実現手順

### Phase 0: 検証ゲート（Week 1〜3、費用: Pro $20 + Workers $5 のみ）
1. **端末実測**: Surface Proの機種・CPU世代・実効RAMを確認。repoをWSL2のext4（~/dev）へ移動、`.wslconfig` で memory=6GB/swap=8GB。ビルド/テスト所要を実測してから工程表を確定する。
2. **ソルバgo/no-go**: 推理問題の一意解ソルバを実Cloudflare Workers上で実測。「1問生成 CPU中央値≤10秒、28問連続生成が15分枠内、成功率≥95%」未達なら探索空間を縮小、なお未達なら**撤退**（損失は$25程度）。
3. **文章品質判定**: テンプレ文のみの28問を自分＋外部3〜5名でブラインド評価（5段階平均3.0が合格ライン）。Haiku 4.5のパラフレーズ品質も28日分実測。
4. **初日にコスト上限を設定**: Anthropicコンソールで Monthly spend limit + auto-reload無効、Cloudflare Budget alerts を$10/$25の二段で設定。

### Phase 1: 実装（基準 Week 4〜10、go判定後にClaude Max $100へ昇格可・累計$400ハードキャップ）
5. クライアント（Vite + TS、静的配信、問題データ非含有）、Worker API（/puzzle/today, /start, /guess, /leaderboard, /health）、D1スキーマ（date主キー）。
6. cron 3本: 週次生成（ソルバ→Haikuパラフレーズ→ゲート→採点→D1格納、バッファ14日）/ 前日21時の翌日分検証 / リーダーボードスナップショット。**0時に動くジョブは作らない**（date駆動でクライアントが日付から問題を選ぶ）。
7. 検収済み静的予備30日分を独立テーブルに常備（生成系全滅時のdegradedモード）。

### Phase 2: 運営装備（基準 Week 11〜14）
8. 監視2系統: Better Stack（外形監視）+ Healthchecks.io（cronのdead-man監視）、いずれも無料。
9. 管理PWA（Cloudflare Accessのpasskey認証）で、スマホから当日問題の無効化・差替をワンタップ実行。kill switch整備。
10. 通報トリアージ: 通報→Haiku一次判定→高確度NGは自動差替、グレーのみDiscord通知。
11. JST 0時直後のPOSTスパイク負荷試験。不合格ならDurable Objects集約へ設計変更。

### 運営フェーズ（継続）
12. 人間の定常作業: 毎日の通知確認5分 + 週1回のClaude Codeセッション（生成システムの語彙・パターン拡充。休んでも配信は止まらない）+ 月次点検15分（支払い・鍵・無料枠消費率）。
13. 月額実費$40超（目安DAU20万）で収益化検討を開始する、と事前にADRへ記録しておく。

### ローカルLLM（Qwen3 4B等）の使い所
14. Surface ProにOllamaを入れ `ollama pull qwen3:4b`（約2.5GB、8GB機で動作可）。用途は**オフラインでの企画ブレスト・テーマ案の下書き量産**に限定し、ゲームの実行経路には置かない。Qwen3は思考モード無効化（enable_thinking=false）を忘れないこと。

## 4. 敵対的検証で潰された落とし穴（避けるべき罠）

検討全体（延べ44エージェント、攻撃9回×3ラウンド）で確定した主な罠:

1. **AWS無料枠での永続ホスティングは2025年7月改定でほぼ消滅**。新規は$200クレジット制で、Freeプランは6ヶ月または残高枯渇で終了、90日以内にPaid化しないとアカウント閉鎖・データ削除。→ 恒久無料はCloudflare/GitHub側に寄せる。
2. **8GB・旧世代CPUのローカルLLMをリアルタイム応答に使う設計は破綻する**（推定1〜4 tok/s、7Bモデルはコンテキスト確保不能）。事前生成・非同期生成に役割を限定する。
3. **「0時に配信cronを実行」する設計は必ず落ちる**。cron遅延・失敗・60日無活動での自動無効化（GitHub Actions）が直撃する。→ 事前配置＋date駆動で「0時に動くものを無くす」。
4. **Batch API（結果返却が最大24時間の非同期）を単一cron内の直列パイプラインに組み込めない**。同期呼び出しにするか、submit/collectの二段に分離する。
5. **無料枠のhard capはDoS一撃で正規ユーザーを道連れにする**（Workers無料10万req/日等）。公開サービスならWorkers Paid $5を保険料として最初から払う方が安全。
6. **従量課金の「気づかない30日」**: Anthropic spend limit（プリペイド＝ハードキャップ）とCloudflare Budget alertsを初日に設定する。
7. **監視の自己参照**: 「障害を検知する仕組み」自体が同じ基盤で動いていると共倒れする。外部SaaSのdead-man方式（pingが来ないことを外側が検知）を使う。なおUptimeRobot無料プランは商用利用がToS禁止。
8. **「無料枠を100%使い切る前提」の見積りは全て甘い**: プロンプトキャッシュ命中・Codespaces枠・Pro枠は「命中すれば得」の期待値扱いにし、予算は非命中の全額で組む。
9. **正解データをクライアントに配るとDevToolsで即ネタバレ**。正解・矛盾構造はサーバ側判定に置き、配布JSONはホワイトリスト方式でビルドする。
10. **「運営を自動化します」という宣言だけの案は敵対検証で必ず落ちた**。「人間が止まってもサービスは劣化するだけで停止しない」縮退経路（自動承認→アーカイブ再放送等）を仕様として実装する。
11. **バスファクター1は自動化では解消できない**。支払い・アカウント・最終責任は人間に残る。「企画から運営まで100%LLM」は3案とも達成不能と結論（最も近づけるのが案B）。
12. **Supabase無料枠は無操作1週間でプロジェクト停止（2026年2月〜）、Vercel Hobbyは商用禁止**。無料バックエンドはCloudflare D1/KVが現状の正解。
